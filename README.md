# swift-parser

Use this package to read typed values from an input by composing parsers. Start from `Parsing`: implement `parse(_:)` for a leaf, or give the conformer a `body` built with `Builder` for a composite. Use `Parser` to wrap a closure or a builder block. The input may be noncopyable or nonescapable, outputs may be noncopyable, and every failure is typed. To write values out, use the sibling package swift-serializer instead. To parse and serialize from one definition, use swift-coder.

## Laws

- The input is the cursor, and a failed parse may leave it partly consumed. Only the backtracking combinators below restore it, and only to the `Restorable` checkpoint they took. Sequencing never restores: builder blocks, `Pair.Parser`, `Append.Parser`, `Skip.Parser`, `Map.Parser`, `Map.Error.Parser`, `FlatMap.Parser` and `Lazy.Parser`. When a later stage fails, the input keeps what earlier stages consumed, and no stage after the failure runs.
- Collection leaves fail without consuming. This covers `Swift.Slice.Parser` and the literal parsers built on it (`Swift.String.Parser`, `Swift.Substring.Parser`, `Swift.Character.Parser`, `Swift.Array.Parser`, `Swift.ArraySlice.Parser`), as well as `Predicate.Parser`, `Search.Selection.Parser`, the `Repetition` and `Cardinal.Range` selections over a collection, `Prefix.Through` and `Prefix.While`. Iterator leaves cannot unread: `First.Where` and the iterator form of `Predicate` consume the element they reject, and `ConsumingLiteral` consumes up to and including the first mismatch.
- A failure is either rejected or committed. `OneOf.Two`, `Optionally`, `Not`, `Many` and `Many.Separated` take a predicate that classifies each failure. When the predicate returns true, the failure is a rejection: the input is restored to the checkpoint and the combinator moves on to the next branch, `nil`, success, or the end of the repetition. Any other failure is committed. It propagates at once, keeps the input it consumed, and no further branch or iteration runs. `Repetition.Parser` splits failures by type instead: `.left` of the operation's `Either` is a rejection, and `.right` is fatal.
- `OneOf.Two` tries its branches in order and returns the first success. When both branches reject, it restores the input and reports both failures.
- `Peek` restores the input after both success and failure. `Not` succeeds without consuming when its upstream rejects, and fails with the input restored when its upstream succeeds. `Backtracking` restores only on failure.
- In `Many`, `Many.Separated` and `Repetition.Parser`, a rejected iteration is rolled back as a whole. That includes a separator consumed before the rejected element, and every element of a multi-parser builder iteration. Earlier iterations stay consumed, including when the result falls short of the minimum. Repetition stops at the upper bound without trying another element. An iteration that succeeds without moving the checkpoint fails with no progress instead of looping. `Repetition.Parser` restores that iteration before failing, and `Many` does not. Bounds are checked when parsing starts, not at construction.
- The builder block passed to `Parser` runs once, at construction, and every parse reuses the composition it built. `Lazy.Parser` caches nothing and calls its factory on every parse. If the factory fails, the input is untouched and the next parse calls the factory again. `FlatMap.Parser` builds a fresh downstream parser from each upstream output.
- `map` obeys the identity and composition laws. Mapping the identity gives the upstream's output and consumption, and two successive maps give the same output and consumption as one map of the composed function. `flatMap` has `Always.Parser` as left and right identity.
- `Swift.Optional.Parser`, which backs a builder `if` with no `else`, produces `nil` only when the parser is absent. A present parser's failure propagates. A `Swift.Result.Parser` that holds a failure throws it without touching the input.
- `Prefix.UpTo` never fails and never consumes the delimiter. `Prefix.Through` includes the delimiter in its output, and fails when the delimiter is absent. `End`, and `parse(_:)` given a whole collection slice by value, fail when input remains and report how many elements are left.
